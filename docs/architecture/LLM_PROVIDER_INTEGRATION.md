## 1. Multi-Model Architecture Overview

Rolevia AI implements a unified, provider-agnostic **LLM Gateway** that eliminates proprietary vendor lock-in. The platform natively supports:
1. **Google Gemini LLMs:** `gemini-1.5-flash`, `gemini-1.5-pro`, `gemini-2.0-flash`
2. **Groq Free Fast Tier LLMs:** `llama-3.3-70b-versatile`, `llama-3.1-8b-instant`, `mixtral-8x7b-32768` (Zero API Cost)
3. **OpenAI LLMs:** `gpt-4o`, `gpt-4o-mini`
4. **Deterministic Local Mock:** Zero-network offline fallback for sandbox testing and CI/CD pipelines without external API keys.

## 3. Dynamic Provider Auto-Selection Logic

`LLMGateway` resolves provider and model dynamically:
1. **Explicit Config:** Passed directly to constructor (`{ provider: 'GROQ', model: 'llama-3.3-70b-versatile' }`).
2. **Environment Variable:** `process.env.LLM_PROVIDER` and `process.env.LLM_MODEL`.
3. **Automatic Key Detection:**
   - If `GROQ_API_KEY` exists → defaults to `GROQ` / `llama-3.3-70b-versatile` (preferred free tier).
   - If `GEMINI_API_KEY` exists → defaults to `GEMINI` / `gemini-1.5-flash`.
   - If `OPENAI_API_KEY` exists → defaults to `OPENAI` / `gpt-4o-mini`.
4. **Deterministic Mock:** If no API keys are present in dev/test, gracefully defaults to `MOCK` with zero network calls and full schema compatibility.

## 4. Native REST Implementations (Zero Extra NPM Dependencies)

In accordance with the project's minimalist engineering rules, all HTTP dispatches use standard Node.js native `fetch`:

### 4.1 Google Gemini REST Protocol
- **Endpoint:** `https://generativelanguage.googleapis.com/v1beta/models/{model}:generateContent?key={GEMINI_API_KEY}`
- **Method:** `POST`
- **Body:**
  ```json
  {
    "contents": [{ "role": "user", "parts": [{ "text": promptText }] }],
    "generationConfig": {
      "temperature": 0.2,
      "maxOutputTokens": 1024
    }
  }
  ```
- **Response Parsing:** Candidate text extracted from `candidates[0].content.parts[0].text`. Token counts retrieved from `usageMetadata`.

### 4.2 Groq Free Fast Tier (OpenAI Compatible)
- **Endpoint:** `https://api.groq.com/openai/v1/chat/completions`
- **Headers:** `Authorization: Bearer {GROQ_API_KEY}`
- **Body:**
  ```json
  {
    "model": "llama-3.3-70b-versatile",
    "messages": [{ "role": "user", "content": promptText }],
    "temperature": 0.2,
    "max_tokens": 1024
  }
  ```
- **Cost Ledger:** Billed as **$0.00** in platform telemetry.

### 4.3 OpenAI Protocol
- **Endpoint:** `https://api.openai.com/v1/chat/completions`
- **Headers:** `Authorization: Bearer {OPENAI_API_KEY}`
- **Body:**
  ```json
  {
    "model": "gpt-4o-mini",
    "messages": [{ "role": "user", "content": promptText }],
    "temperature": 0.2,
    "max_tokens": 1024
  }
  ```

## 5. Strict Guardrails & Anti-Hallucination Invariants

The LLM Gateway operates under four immutable security invariants:

1. **Zero Hallucinated Metrics:** Every quantitative claim (e.g., "boosted revenue by 40%", "$5M volume") generated by an LLM is post-validated via `validateSemanticClaimAssertions`. Ungrounded assertions trigger immediate `HALLUCINATION_DETECTED` errors.
2. **Prohibited Sensitive Disclosures:** The LLM is strictly prohibited from guessing or generating answers for:
   - Visa sponsorship and citizenship
   - Desired compensation and salary expectations
   - Disability, veteran status, or demographic data
   - Any question matching these triggers returns `requiresHumanIntervention: true` and `draftAnswer: null`.
3. **Anti-Receipt Fabrication:** The gateway scans all LLM completions with regex `/gh-conf|ashby-app|workday-ref|receipt-token|confirm-[a-f0-9]{8}/i`. Any attempt by an LLM to simulate or fabricate confirmation numbers throws `FORBIDDEN_OUTPUT`.
4. **Decoupled Billing & Submissions:** LLM prompts have zero access to database payment tokens, Stripe/Razorpay secrets, or submission execution buttons.
